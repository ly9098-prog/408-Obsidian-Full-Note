# P4强化：HTTP 报文与协议封装速记

> [!abstract] 复习范围
> 看懂 **请求行 / 状态行、首部、空行、实体主体**，串起一次 Web 访问中的协议封装。

## 1. 请求与响应：先看第一行

### 请求报文

```text
方法  URL  版本 CRLF       ← 请求行
字段名: 值 CRLF           ← 首部行，可有多行
...
CRLF                      ← 空行，结束首部
[实体主体]                ← 可选
```

### 响应报文

```text
版本  状态码  短语 CRLF    ← 状态行
字段名: 值 CRLF           ← 首部行，可有多行
...
CRLF                      ← 空行，结束首部
[实体主体]                ← 可选
```

> [!important] 第一行区分类型，空行区分首部与主体
> 请求报文以 **方法** 开头，响应报文以 **版本** 开头。
> **CRLF** 表示回车换行；首部结束后有一个空行，即使没有实体主体也要注意这一结构。

## 2. 方法与状态码

| 类型 | 名称 | 408 记忆点 |
| --- | --- | --- |
| 请求方法 | **GET** | 获取资源；本资料 GET 例题中的请求主体为空 |
| 请求方法 | **POST** | 提交或上传数据，请求中可携带实体主体 |
| 请求方法 | **HEAD** | 请求资源的首部信息，响应不返回实体主体 |
| 状态码 | **200** | 请求成功 |
| 状态码 | **404** | 请求的 URL 资源不存在 |

## 3. 一次 Web 访问的协议链

1. **解析地址**：DNS 查询通常通过 **UDP / 53** 获得服务器 IP 地址。
2. **建立连接**：本资料的 HTTP 场景使用 TCP，服务器熟知端口为 **80**。
3. **发送报文**：HTTP 报文交给 TCP，再依次封装为 IPv4 数据报和以太网帧。
4. **接收解封装**：接收端按相反顺序处理各层首部。

| 层次 | 本例协议 | 数据单位 |
| --- | --- | --- |
| 应用层 | HTTP | 请求 / 响应报文 |
| 传输层 | TCP | TCP 报文段 |
| 网络层 | IPv4 | IP 数据报 |
| 数据链路层 | Ethernet | MAC 帧 |

> [!warning] 分清 HTTP 的性质与 TCP 的性质
> 按 408 教材表述，HTTP **无连接、无状态**；本例通过面向连接的 **TCP** 传输。
> 长度计算时，将完整 HTTP 报文视为 TCP 的应用数据，再按题设 MSS 和各层首部计算。
