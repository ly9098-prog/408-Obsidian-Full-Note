# P4强化：逐层协议封装与 TCP/UDP 计算

> 来源：用户提供的《计网P4：各层协议封装串讲、路由选择协议》；与已有 UDP 分片笔记互补，重点保留协议封装关系、端口速记和综合计算。

## 1. 常见协议的承载关系

| 协议 | 承载/封装位置 | 熟知端口或协议号 | 408 记忆点 |
|---|---|---:|---|
| HTTP | TCP | 80 | 无状态；可用 Cookie 跟踪会话 |
| FTP 控制连接 | TCP | 21 | 传 FTP 命令/应答，控制连接长期保持 |
| FTP 数据连接 | TCP | 20 | 主动模式下由服务器从 20 端口发起 |
| SMTP | TCP | 25 | 邮件发送，推送（push） |
| POP3 | TCP | 110 | 用户代理从服务器拉取邮件 |
| BGP | TCP | 179 | 外部网关协议 |
| DNS | UDP 为主，也可 TCP | 53 | 普通查询短而快；大响应或特殊场景可用 TCP |
| DHCP | UDP | 服务器 67，客户端 68 | 两端端口固定 |
| RIP | UDP | 520 | 内部网关协议 |
| ICMP | 直接放在 IP 数据报数据部分 | IP 协议号 1 | 不经过 TCP/UDP |
| OSPF | 直接放在 IP 数据报数据部分 | IP 协议号 89 | 不经过 TCP/UDP |
| ARP | 直接封装在以太网帧 | EtherType 0x0806 | 链路层协议 |
| PPP | 点对点链路帧 | - | 不基于 TCP/UDP |
| PPPoE | PPP 帧再放入以太网帧 | - | “链路层套链路层” |

## 2. 长度计算规则

题设常用：以太网 MTU=1500 B，IPv4 首部=20 B，TCP 首部=20 B，UDP 首部=8 B。

- UDP 长度字段 = UDP 首部 + UDP 数据，**包含 UDP 首部**。
- IPv4 总长度 = IP 首部 + IP 载荷（TCP 段或 UDP 数据报）。
- 标准以太网帧长度 = 14 B MAC 首部 + IP 分组 + 4 B FCS；若数据字段不足 46 B，帧按最小帧长补齐，最小帧长为 64 B。
- TCP 的 MSS 只表示 TCP 数据部分上限，不含 TCP 首部；典型以太网 IPv4 场景 `MSS=1500-20-20=1460 B`。
- TCP 按 MSS 在传输层分段；IP 是否分片取决于每个 IP 分组是否超过下一跳链路 MTU，二者不要混淆。

## 3. 综合例题（MTU=1500 B）

应用层一次产生 3200 B 数据。

### TCP 发送

按 `MSS=1460 B` 分成 `1460 + 1460 + 280` 三个 TCP 段：

| TCP 数据 | TCP 段长度 | IP 总长度 | 以太网帧长 |
|---:|---:|---:|---:|
| 1460 | 1480 | 1500 | 1518 |
| 1460 | 1480 | 1500 | 1518 |
| 280 | 300 | 320 | 338 |

每个 IP 分组均不超过 1500 B，因此不会发生 IP 分片。

### UDP 发送

UDP 一次性交付 3200 B：

- UDP 总长度/长度字段：`8+3200=3208 B`。
- 原始 IP 总长度：`20+3208=3228 B`，超过 MTU，必须由 IP 层分片。
- IP 载荷为 3208 B，非末片最大载荷为 `1500-20=1480 B`，且 1480 是 8 的倍数。

| 分片 | IP 载荷 | IP 总长度 | 片偏移 | MF | 帧长 |
|---|---:|---:|---:|---:|---:|
| 1 | 1480 | 1500 | 0 | 1 | 1518 |
| 2 | 1480 | 1500 | 185 | 1 | 1518 |
| 3 | 248 | 268 | 370 | 0 | 286 |

UDP 首部只在第 1 片中；后三片只属于同一个 IP 数据报的载荷，接收主机收齐并重组后才交给 UDP。

### DNS/握手/GET 的短题模板

- DNS 应用数据 40 B：UDP 长度 `48 B`，IP 总长度 `68 B`，以太网帧长 `86 B`。
- TCP SYN 不带数据：TCP 段 `20 B`，IP 总长度 `40 B`；以太网数据字段需补齐到 46 B，帧长 `64 B`。
- HTTP GET 应用数据 200 B：TCP 段 `220 B`，IP 总长度 `240 B`，帧长 `258 B`。

## 4. MTU=800 B 的变题

UDP 总长度仍为 `3208 B`，与 MTU 无关；原始 IP 总长度仍为 `3228 B`。

- 单片最大 IP 载荷为 `800-20=780 B`。
- 除最后一片外，载荷必须是 8 B 的整数倍，因此实际取 `776 B`，不能取 780 B。
- `3208=776×4+104`，共 5 片：

| 分片 | IP 载荷 | IP 总长度 | 片偏移 | MF | 帧长 |
|---|---:|---:|---:|---:|---:|
| 1 | 776 | 796 | 0 | 1 | 814 |
| 2 | 776 | 796 | 97 | 1 | 814 |
| 3 | 776 | 796 | 194 | 1 | 814 |
| 4 | 776 | 796 | 291 | 1 | 814 |
| 5 | 104 | 124 | 388 | 0 | 142 |

## 5. MSS 如何确定

- MSS 在 TCP 三次握手的两个 SYN 报文段中以选项通告，含义是“发给我的 TCP 段数据部分不要超过这个值”。
- 两个方向的 MSS 可以不同，发送方应按对端通告值分段。
- 若未携带 MSS 选项，IPv4 场景通常按 536 B 的安全值发送（按考纲记忆即可）。
