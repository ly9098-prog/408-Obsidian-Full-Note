## 1. 常见协议的承载关系

### 通过 TCP / UDP 承载

| 协议 | 承载 | 熟知端口 | 408 记忆点 |
| --- | --- | --- | --- |
| HTTP | TCP | **80** | 无状态；可用 Cookie 跟踪会话 |
| FTP 控制连接 | TCP | **21** | 传命令与应答，控制连接长期保持 |
| FTP 数据连接 | TCP | **20** | 主动模式下，服务器从 20 端口发起 |
| SMTP | TCP | **25** | 邮件发送，推送（push） |
| POP3 | TCP | **110** | 用户代理从服务器拉取邮件 |
| BGP | TCP | **179** | 外部网关协议 |
| DNS | UDP 为主，也可 TCP | **53** | 普通查询常用 UDP，大响应等可用 TCP |
| DHCP | UDP | **服务器 67 / 客户端 68** | 两端端口固定 |
| RIP | UDP | **520** | 内部网关协议 |

### 直接封装在 IP 或链路层

| 协议 | 封装位置 | 标识或记忆点 |
| --- | --- | --- |
| ICMP | IP 数据报的数据部分 | IP 协议号 **1** |
| OSPF | IP 数据报的数据部分 | IP 协议号 **89** |
| ARP | 以太网帧 | EtherType **0x0806** |
| PPP | 点对点链路帧 | 不基于 TCP / UDP |
| PPPoE | PPP 帧再放入以太网帧 | “链路层套链路层” |

> [!warning] 端口号、IP 协议号、EtherType 分属不同层次
> ICMP、OSPF **不经过 TCP / UDP**；ARP 直接封装在以太网帧中。

## 2. 长度计算规则

> [!note] 本页统一题设
> 以太网 **MTU = 1500 B**，IPv4 首部 **20 B**，TCP 首部 **20 B**，UDP 首部 **8 B**。
> 下列基础计算按无 IP / TCP 选项、允许 IP 分片处理；帧长不计前导码和帧间间隔。

| 计算对象 | 计算式 | 注意点 |
| --- | --- | --- |
| UDP 长度字段 | UDP 首部 + UDP 数据 | **包含 UDP 首部** |
| IPv4 总长度 | IP 首部 + IP 载荷 | IP 载荷包含传输层首部 |
| 以太网帧长 | 14 B + max(IP 分组长度, 46 B) + 4 B | 最小 **64 B**，注意填充 |
| TCP 的 MSS | 本例为 1500 − 20 − 20 = **1460 B** | 仅指 TCP 数据部分 |

> [!important] TCP 分段与 IP 分片分开判断
> **TCP 分段**：传输层按 MSS 切分应用数据。
> **IP 分片**：网络层判断 IP 分组是否超过下一跳链路 MTU。

## 3. 综合例题（MTU = 1500 B）

**题设**：应用层一次产生 **3200 B** 数据。对照 TCP 和 UDP 两种发送方式。

### TCP：先按 MSS 分段

1. **算 MSS**：`1500 − 20 − 20 = 1460 B`。
2. **分应用数据**：`3200 = 1460 + 1460 + 280 B`。
3. **逐层加首部**：每段加 TCP 首部，再加 IP 首部，最后算帧长。

| TCP 数据 / B | TCP 段长度 / B | IP 总长度 / B | 以太网帧长 / B |
| ---: | ---: | ---: | ---: |
| 1460 | 1480 | 1500 | 1518 |
| 1460 | 1480 | 1500 | 1518 |
| 280 | 300 | 320 | 338 |

**结论**：每个 IP 分组均不超过 1500 B，**不发生 IP 分片**。

### UDP：先封装，再由 IP 分片

1. **算 UDP 长度**：`8 + 3200 = 3208 B`。
2. **算原 IP 总长度**：`20 + 3208 = 3228 B`，超过 MTU。
3. **切分 IP 载荷**：非末片最大载荷为 `1500 − 20 = 1480 B`，满足 8 B 对齐；得到 `1480 + 1480 + 248 B`。

| 分片 | IP 载荷 / B | IP 总长度 / B | 片偏移 | MF | 帧长 / B |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 1480 | 1500 | 0 | 1 | 1518 |
| 2 | 1480 | 1500 | 185 | 1 | 1518 |
| 3 | 248 | 268 | 370 | 0 | 286 |

> [!warning] 只给第 1 片保留原来的 UDP 首部
> **每片都加 IP 首部，但不重复加 UDP 首部。**
> 接收主机先重组 IP 数据报，再将完整的 UDP 数据报交给 UDP。

### DNS / 握手 / GET：短题对照

| 场景 | 应用数据 / B | UDP 或 TCP 长度 / B | IP 总长度 / B | 帧长 / B |
| --- | ---: | ---: | ---: | ---: |
| DNS 查询，使用 UDP | 40 | 48 | 68 | **86** |
| TCP SYN，无数据、无选项 | 0 | 20 | 40 | **64** |
| HTTP GET，使用 TCP | 200 | 220 | 240 | **258** |

**SYN 题的填充**：IP 分组只有 40 B，以太网数据字段补齐至 46 B，帧长为 `14 + 46 + 4 = 64 B`。

## 4. MTU = 800 B 的变题

**不变量**：UDP 总长度仍为 **3208 B**，原始 IP 总长度仍为 **3228 B**。

1. **扣除 IP 首部**：`800 − 20 = 780 B`。
2. **向下按 8 B 对齐**：非末片实际最大载荷为 **776 B**。
3. **计算分片数**：`3208 = 776 × 4 + 104 B`，共 **5 片**。
4. **算偏移**：每个完整非末片使后续偏移增加 `776 ÷ 8 = 97`。

| 分片 | IP 载荷 / B | IP 总长度 / B | 片偏移 | MF | 帧长 / B |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 776 | 796 | 0 | 1 | 814 |
| 2 | 776 | 796 | 97 | 1 | 814 |
| 3 | 776 | 796 | 194 | 1 | 814 |
| 4 | 776 | 796 | 291 | 1 | 814 |
| 5 | 104 | 124 | 388 | 0 | 142 |

> [!warning] MTU 是上限，不要求每片都装满
> 非末片载荷不能直接取 **780 B**，必须满足 8 B 对齐，所以本例 IP 总长度最大为 **796 B**。

## 5. MSS 如何确定

- **何时通告**：在三次握手中携带 SYN 标志的报文段里，通过 MSS 选项通告。
- **表达含义**：“发给我的 TCP 段，**数据部分**不要超过这个值。”
- **方向差异**：两个方向的 MSS 可以不同，发送方受对端通告值约束。
- **默认记忆**：IPv4 场景下，未携带 MSS 选项时，按 **536 B** 的默认值记忆。
